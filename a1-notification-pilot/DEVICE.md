# A1 设备连接与图片显示

## 当前结论

迁移初版A1只有Mock链路，原A5安卓端只有文字协议，不能直接声称能够显示新的PNG。现已移植原程序的ADB端口转发、持久套接字、设备绑定、事件账本、前台守护和scrcpy控制，并增加图片预传、哈希检查、双眼绘制及隐藏回执。

A1应用包名为`link.ironip.a1.rayneo`，协议`a1-rayneo/1`，套接字`a1-rayneo-v1`。Java类命名空间保留`link.ironip.a5.rayneo`，因此启动组件是`link.ironip.a1.rayneo/link.ironip.a5.rayneo.MainActivity`。A1与原A5应用及数据独立；旧APK不支持本图片协议。

## 操作

1. 安装Android platform-tools和scrcpy，USB连接眼镜并在设备上授权调试。当前Mac已安装scrcpy，运行`adb devices -l`应看到状态device。
2. 安装[构建说明](rayneo-display/BUILDING.md)生成的A1 APK，也可在后台“准备与检查”下载本机构建产物。首次需要通过ADB安装：`adb -s <序列号> install -r <APK路径>`。
3. 打开`http://127.0.0.1:5189/admin`，切换“准备与检查”，扫描设备、选择并绑定，再点击唤醒/打开显示端。状态应同时满足连接成功、显示就绪、图片协议可用。
4. 点击scrcpy查看左眼画面，选择材料并预览，保持4000ms发送，核对眼镜和回执。正式任务运行时禁止手动覆盖图片、切换设备或重新拉起应用。
5. 新会话明确选择Mock或真机模式。默认Mock；没连接设备仍可启动后台和Mock实验。选择真机后，未就绪会明确报错，不会自动换成Mock。

后台串口选择保存在运行数据库。可用`A1_RAYNEO_SERIAL`设置初始设备，`A1_ADB_PATH`、`A1_SCRCPY_PATH`指定命令路径；未设置时使用PATH。前台守护设置同样持久保存；无设备时显示等待连接。守护只在空闲时恢复显示端，权限备份用于恢复原设备状态。

## 图片与稳定性机制

- 原始PNG先经本机SHA-256校验，再传到A1应用外部目录，由安卓再次校验、解码和缓存；正式任务开始前完成准备。
- 双眼黑底居中，宽284px、保持宽高比、不裁切。亮度沿用`1.0f / 6.0f`，该比例不等于已测得1000nits。
- 显示指令使用永久request_id；同一请求内容重复不会再次显示，内容冲突拒绝。电脑先保存发送意图；超时标记unknown，不自动重播，避免重复刺激。
- accepted仅表示收件，drawn和hidden分别记录双眼绘制与清除回调。程序保留原设备时钟及事件，不把发送成功当作已显示；回调也不是光学测量。
- 图片固定4秒，鼠标和空格只用于持续运行的2-back，不提前关闭图片。A1图片路径没有提示音。
- 手动调试与正式请求分别记录；手动发送不进入被试成绩。断线不会自动重放正式刺激，主试应中断并重跑受影响尝试。
- 诊断可下载设备记录；实验ZIP另含该会话正式device_requests.json，保存绑定、图片身份、发送结果及原始设备事件。

## 时间分析限制

电脑浏览器与安卓单调时钟之间尚未完成映射。真机请求时刻仅表示发送意图；不能据此认定实际曝光起点。当前真机前/中/后真实曝光窗口为unknown，QC标记device_clock_mapping_pending；对应通知效应不能作为正式结果使用。Mock仍按同浏览器时钟计算。连接控制和手动图片检查可先使用，正式真机数据采集前仍需完成时钟映射和物理验收。
